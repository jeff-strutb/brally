# Mac sfx

*Recorded 2026-09-29.*

> Mac 32-bit lane sound effects wired 2026-09-29 (DirectSound mixer in host_dx.c + native/sound.m); the three defects that kept every SFX silent, and how to verify against brbox

2026-09-29: game SFX play natively in the wasm lane. Game SFX = DirectSound only (EAR is used only for the CD music channel).
- host_dx.c mixes the static DS buffers (DS gain/pan laws, Hermite resample, per-block gain ramp); native/sound.m = AVAudioEngine source node -> peak limiter, muted when app inactive (no DSBCAPS_GLOBALFOCUS). BR_SFX=0 off; BR_SFXWAV records (headless = manual-rendering offline, needs BR_VCLOCK for game-time length); BR_SFXQUIET records a windowed run at zero volume.
- Why nothing played before: (1) host mmioGetInfo/Advance were stubs, BrWavReadData reads through the MMIOINFO buffer; (2) mmioDescend with fl=0 compared the caller's uninitialised ckid; (3) BrWaveSeekData bare `return;` (MSVC eax), plus br_musiccmd.c's empty BrExt_* stand-ins (menu clicks, race one-shots) -- fixed with @replaces in sound.m.
- **How to apply:** empty local stand-ins with a symmap VA are a recurring lane defect class (music hit it too) -- grep a module for them before blaming the host. Verify DS behaviour by diffing `BRBOX_COMTRACE=IDirectSound tools/brbox.py run --script ...` against the port; matched frame-for-frame to f1039 on 20_quickrace_drive, later drift is race-sim divergence. 50_championship "line 22 timed out" is pre-existing.
