- [capstone-venv-auditors](capstone-venv-auditors.md): The capstone-based auditors (claimcheck/crossdiff/dumpasm/globals) need a venv; how to restore and run them.
- [crank-daemon](crank-daemon.md): tools/brally/crank.py is the unattended byte-exact cranker (2026-09-07) -- how to run it, what it did on day one, and the loop it needs a person for (miss -> hand-solve one -> new lever)
- [filing-and-description-gate](filing-and-description-gate.md): tools/brally/fileaudit.py gates BOTH halves of rule 6 (module filing + WHAT IT DOES comment) with ratcheting baselines. config/brally/filing.csv is the durable per-function module record. autofile.py used to slice-dump every match by address, which caused the 570-function backlog.
- [fnmatch-harness](fnmatch-harness.md): tools/brally/fnmatch/ = per-function matching sandbox: ~1.5s edit->compile->score cycle, per-tag isolation so N workers probe one function concurrently, and the register-blind multiset metric. Use it instead of the 20-min sweep.
- [generated-dir-retired-2026-09-28](generated-dir-retired-2026-09-28.md): 2026-09-28 src/brally/core/generated/ emptied and deleted -- every body refiled into its module, byte-identical; refile helpers, traps, and the \"project lead wants architectural correctness, not port\" rule
- [ghidra-pipeline](ghidra-pipeline.md): Ghidra auto-decomp pipeline - tree 474/1047 tagged match; sigaudit.py epilogue audit produced +18 matches in one pass; BrTex3dRegister parked at allocator frontier; resume by working the remaining flagged audit rows.
- [msvc-version](msvc-version.md): Original binaries compiled with MSVC 5.0 (Visual Studio 97), linker 5.0, March 1999. Needed for matching decomp builds.
- [perm-exe-tooling](perm-exe-tooling.md): tools/brally/perm_exe.py drives the deterministic permuter (permute.py) at in-scope EXE functions (orig_<exe> bins + /ML//MT//MD opts). permute.py's anneal is generic; only its seed/orig loaders were DLL-keyed.
- [reference-glide-sdk-and-c2read](reference-glide-sdk-and-c2read.md): Glide 2.x SDK headers (tools/toolchains/glide2x-sdk via setup.sh) and tools/brally/c2read (VC5 C2 allocator/frame/symbol-id reader) - use for order-only and register walls on the PC decomp
- [refile-byte-identity-2026-09-25](refile-byte-identity-2026-09-25.md): All 66 T3/T4 functions refiled out of slice*.c byte-identically (2026-09-25); how: per-function snapshot compare, position sweep for TU state, fileaudit now fails T3-in-batch
- [src-is-msvc-only-port-specs-2026-09-28](src-is-msvc-only-port-specs-2026-09-28.md): Since 2026-09-28 src/brally/ and src/brally/include/ carry no BR_MATCHING_BUILD/_MSC_VER conditionals; Mac-port differences are name-keyed specs in ports/brally-wasm/patch/, applied by portgen.py
- [sweep-is-incremental-now](sweep-is-incremental-now.md): match_sweep.py now writes back on every run and caches by content hash - full sweeps are no longer needed to re-baseline.
- [toolchain-self-contained](toolchain-self-contained.md): The matching-build toolchain must live inside the repo - Wine downloaded to tools/brally/, MSVC extracted from the ISO. Never install to the host.
- [vc42-is-the-real-compiler](vc42-is-the-real-compiler.md): VC++ 4.2 (cl 10.20.6166) staged at tools/toolchains/msvc42; it breaks a codegen wall VC5 can't, but the cross-check says BRGlide is dominantly VC5 - 4.2 is at most a few mixed-in TUs, NOT a project-wide swap
- [vc42-not-brglide](vc42-not-brglide.md): VC++ 4.2 cross-check RUN and FAILED for BRGlide.dll - 5.0 byte-exact functions break under 4.2; keep MSVC 5.0 for the DLL
- [vc4x-version-hypothesis-refuted](vc4x-version-hypothesis-refuted.md): BrCarStateEncodeDelta's residue is NOT a VC4.x version gap - all 4.0/4.1/4.2 builds emit identical bytes; it's a register-colouring wall
