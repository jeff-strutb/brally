# Idioms found (token b560e084)

## Vestigial param + internal clock read (BrTicks30FromMs 0x100037D0)
A function whose declared param is UNUSED by the original: the body reads a
global/clock itself. Keep the param in the signature (it emits no code, so no
shared-header edit needed) and read the real source internally. Distinguisher:
recomp loads the param from [esp+4]; orig has `call <helper>; mov <sav>,[glob];
sub`. Residual after fix was a pure div-vs-magic-mul SCHEDULING order (orig
emits the `%100` hardware `div` before the `/100` magic multiply); MSVC5 fixes
that order regardless of C addend/local form -> coloring/schedule wall.

## Partial body = arithmetic leaf missing its guards+backend call (BrCdVolumeScale 0x10002D60)
When a "partial" C body recompiles far smaller than orig, the original often
wraps the arithmetic in guard(s) + a backend call. Mirror the sibling that
shares the guard pattern; the backend is an adjacent function-pointer slot
(here g_575454, one dword above g_575470). 2-arg call, no stack cleanup after
= __stdcall fn pointer. NOTE: define/move the function BELOW the globals it
references (leaf funcs earlier in the file can't see mid-file externs).

## Restore sprintf-buffer DEVIATION for the CHK_* family (BrFChkFRead 0x10003430)
The five CHK_* helpers deviate: original formats into a 0x400 prologue-allocated
`char buf[0x400]` via wsprintfA and ships to OutputDebugStringA before exit(1).
The port replaced this with fprintf(stderr). Restore under BR_MATCHING_BUILD
(char buf as a FUNCTION-level local so `sub esp,0x400` lands in the prologue).
Residual = a 2-var size<->count callee-saved (ebx/edi) coloring swap MSVC5 will
not flip from any multiply/compare operand order.

## Portable BrFtol emulation blocks the __ftol tail-jump (BrFixPackU24Q13 0x10006A50)
When a file carries a static software BrFtol(double), calling it emits
`fstp qword [esp]; call BrFtol` and spills the value to memory. The original
instead tail-jumps the CRT _ftol (0x10074560): use a PLAIN `(int32_t)d` cast in
the BR_MATCHING_BUILD path -> `jmp __ftol`, value stays in ST(0). Also: scale/
bias must be FLOAT literals (0.5f, -8192.0f) so fmul/fsubr are `dword`, not
`qword`.

## Direct Win32 + intrinsic string ops behind a host abstraction (BrBaseDirInit 0x10063860)
The port abstracts Win32 registry reads behind a callback fn-ptr and uses
strncat helpers. The original calls RegOpenKeyExA/RegQueryValueExA/RegCloseKey
directly and inlines strlen (`repne scasb`), strcat and strcpy (`rep movsd` +
`rep movsb`). Restore under BR_MATCHING_BUILD with `#include <windows.h>` +
`#pragma intrinsic(strlen, strcpy, strcat)`.
DISTINGUISHER (the last wall): a bare `strcpy(dst, "c:\\")` of a <=4-byte string
literal CONSTANT-FOLDS to a single `mov dword [dst],imm` under this MSVC5, but
the original emits the generic runtime strlen+rep movsd copy. Force the generic
form by routing the source through a `const char *tmp = LIT; strcpy(dst, tmp);`
temp -- the pointer indirection defeats the fold. (strcat never folds: its dest
offset is a runtime strlen, so it always emits the generic copy.)
