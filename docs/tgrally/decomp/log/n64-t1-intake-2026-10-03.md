Levers that paid (IDO 5.3):
- An early exit as `continue` (not a positive if) gives the ROM's loop shape: pointer walk + count>0 guard (BrSkidDraw), s-reg numbering (BrWheelSprayEmit), <=/>= float early-outs (BrParticleListDraw).
- Integer literals for float stores/decrements (`x = 0`, `x -= 1`) stop IDO hoisting 1.0/0.0 into saved FP regs; `< 0` int compares get their own zero register.
- Unused one-int arrays `int uN[1]` placed between named locals reproduce ROM frame gaps (fillsweep.py: 2^n placements); unused scalars do NOT take slots, arrays do.
- Struct copy `a = *(BrVec3*)p` vs per-component copy vs float[3] array changes whether the copy lives in memory -- probe all three.
- Chained `v1->f = v0->f = x` stores the inner (v0) first; pick chain direction from the ROM store order.
- `(signed char) = c->f = *p++` chain order decides lbu+sext vs lb.
- Repeated pad-record expression `*(unsigned int *)(&D_8036A8E0 + D_8028DBBC * 0x15c)` at every test (no `pad` local) matched the menu pad logic.
- A local `float x[3] = {...}` / `char *s[2] = {...}` initialiser is copied from the object's .data; its position in .data proves the TU (BrCarAxleGrip/BrWheelTyre share rbforce.c's .data; the paint popups share one object).
- When a file's .rodata cannot map (paintshop.c is a grab-bag), give contiguous-string functions their own file (paintmenus.c).
- A constant the ROM spills to a temp and re-loads (`addiu a1,0xe6; sw a1,0x4c(sp)` ... `lw`), instead of folding it into a sum: hold it in a block-scoped `int ax[1]` (arrays are never constant-propagated). Got BrPaintTextStyleMenu from 68 to 5 register-blind.
- Store order of a constant table: chains `r[0][2] = r[1][2] = 0x40;` store left-to-right pairs; sweep the six chain shapes and read the sw order.
- Paint-shop popups: each gets its own file (the grader takes .rodata/.data bases per file); big ones (BrPaintClick) compile like the ROM with all locals in the frame; the case-body ORDER in the source must follow the ROM's block order, and `if (x) {} else {...}` reproduces a ROM whose then-block is the branch target.
- OR-packing (RGBA5551): IDO rotates the last OR term to the front; put the `(old & 1)` term LAST to get the ROM's order.
- One local shared by two values (errnum, then the buttons) puts them in one register: BrPadMapRead went T4 on that (`int b` for both).
- Unsigned DXT: when the ROM uses divu for a LoadBlock dxt, cast the TXL2WORDS divisor `(unsigned)`.
- A ROM `ori rX, zero, K` for a store of a constant into a just-zeroed field = source `|= K` after `= 0`.
- ROM `addiu sX,zero,K` + `multu idx,sX` for a record index (K = 0x15C pad) = an UNSIGNED multiply in the source: `D_8028DBBC * sizeof(BrPadRec)`. Signed gives sll/subu. Cheap K (0x2090, 0x24) stay shifts even unsigned -- the ROM's multu there is NOT reproducible this way (BrPaintShopScreen residue).
- No `pad`/`pressed` locals in the paint popups: re-address `*(unsigned int *)(&D_8036A8E0 + D_8028DBBC * ...)` at every test (BrPaintBrushSelect, BrPaintOvalStyleSelect, BrPaintStyleSelect -> T4).
- A per-iteration x written inline (`i * 76 + 175`) instead of an induction local fixed s-reg order (BrPaintStyleSelect).
- Compare against a register-held constant in variable-first order (`bne v0,a0`): assign the constant to a dead local inside the test (`s != (n = 3)`) (BrWheelSprayEmit T4).
- Peer lever: a struct field IDO reloads after stores (m->parts) -> explicit local `parts = m->parts`.
- Speed compared into a local in the test (`(speed = car->xfe4[0]) > 40`) changed evaluation order of a later sum.
