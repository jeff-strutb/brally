# BrCarDrawVehicle (0x1000A110) idioms - session 2026-08-31

Proven by byte diffs against BRGlide orig; each one moved the REGNORM gap.

## 1. Colour/RGBA packs are HORNER form, never independent shifts
`(((top<<8 | b1) << 8 | b2) << 8) | a` - NOT `top<<24 | b1<<16 | b2<<8 | a`.
The first two components go through byte registers (`mov dh,al` = a
`(uint8_t)x << 8` into a zeroed accumulator; `mov dl,al` = `| (uint8_t)x`);
a component spelled `& 0xFF` gets a full-register `and`/`or`. Proven at the
fog put (0xb5), the FB envcolour (0x1928 x3), the ftol colourA (0x2c6).

## 2. Branch arms each contain their own put() - no value-then-put
A 3-arm value selection with one `put(v)` after compiles to one pack and a
join. The orig has the FULL pack duplicated per arm (cross-jump merges only
arms whose generated bytes are identical - the 0x427 tail merge of arms
2/3). Spell `put(...)` inside each arm. Worth ~90 B at the FB site alone.

## 3. `x ? K1 : K2` inline per emit - the neg/sbb select
Cull pair at 0xaa83: each of the two puts carries its own
`(a ^ b) ? K1 : K2` (xor; neg; sbb; and K1-K2; add K2), both globals
re-read for the second put. An if/else into locals produces branches.

## 4. Recompute-per-site beats caches - caches ROTATE the allocation
The original re-derives from memory at every use site:
- icar (`car+0x140`) for every lights payload/byte store (bases fold:
  0x102733b0/b1/b2 = lights+0x10/11/12),
- lodOff `(lod*5)<<3` inline at the 0x8038/0x8030 sites, assigned only at
  the 0x8024 site (into the dead pCar ARG slot),
- bKind `car+0x29af` (5 reads, never cached),
- the track-flags pointer read inline in the index expression.
Every cached local we removed (dst, i, lodOff-early, bKind, flags ptr)
shifted register assignment; after the icar/movsd fix the WHOLE-FUNCTION
rotation snapped: car=ebx, zero=ebp, load-then-cmp guard - all free.
Confirms register-rotation-is-a-symptom at scale.

## 5. Byte-slot pack locals: stores kept via volatile, reads still a wall
Orig stores two byte locals ([esp+0x31]/0x32) and reads them back as
DWORD+`and 0xff` in four pack tails. Plain uint8_t locals get store-
forwarded (stores deleted, `mov dl,al`). `*(volatile char *)&pack[n] = v`
keeps the stores byte-exact; the READ `pack[n] & 0xFF` still narrows to a
byte load when a byte register is free. `*(volatile int32_t*)&` on the
read forces the dword but blows register pressure (stole ebp). UNSOLVED
residue ~10 insns; the deciding difference is that orig starts the
colourB pack while colourA still occupies edx (accumulator moves to ecx).

## 6. VC4.2 cross-check (this TU): NOT the compiler for BRGlide
tools/toolchains/msvc42 cl.exe /O2 on this TU: all four byte-exact-under-5.0
functions come out smaller and structurally different (BrGuMtxStore 39B
vs 47B, BrCarDrawWheels 807B vs 932B, BrCarDrawBody 1357B vs 1576B), and
BrCarDrawVehicle loses the interleaved-push prologue and the ebp
zero-reg. MSVC 5.0 stays the BRGlide compiler.

## Open walls (this function, ranked)

- Dir0 else-arm copy: orig `fld z; fld y; mov eax,x; fstp y; mov x; fstp z`

- frame 0x40 vs 0x4c (12 B; some locals still live in wrong homes)
- flag290C esi vs edi (one transposition, likely downstream of the above)
