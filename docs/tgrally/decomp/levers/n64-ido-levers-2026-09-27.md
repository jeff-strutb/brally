`tools/tgrally/n64box_scripts/*.txt` in n64box with a UC_HOOK_CODE on each function entry,

IDO levers that each flipped functions to EXACT (Ghidra → original spelling):
- pointer-walk do/while to `&END` → `for (i..N) f(arr[i])` over typed arrays.
- `0.0` → `0.0f` (Ghidra prints single constants as double). Generator opt `fsuf`, tree lever `n64lever.py --lever fsuf`.
- `&DAT_x + n*K` is BYTE arithmetic (Ghidra's `undefined` = 1 byte); generator retyping to int scales ×4. Opt `bytes` / lever `bytes`.
- nested `bVar=0; if(..){bVar=0; if(..) bVar=cond;}` → one `return a && b && c`.
- `r = 1.0f/len` → reuse `len = 1.0f/len` (moves zero const to $f12).
- fixed high-RAM buffers (0x803C8000 model bufs) are LINKED symbols (lui/addiu), not constants: `extern T D_803C8000[]`. Gen opt `negsym`.
- register-role swaps: a value used in several places may be a re-read global expression IDO CSEs, not a local (BrCarPickKind); a stored field read back (`car->slot = ...; if (car->slot < 2)`) numbers temps differently from a local.
- block order: IDO lays blocks in source order; ROM's fallthrough path = the source's then-branch.
- `li tX,0; li tY,0; sw` pairs = a 64-bit (u64/OSTime) variable. A u64 DEFINED in the TU (`unsigned long long D_x = 0;`, it is zero .data) stores lo-then-hi under one lui; `extern` splits it. u32→u64 assignment gives `li t0,0` for the hi word. Linker resolves the defined symbol by name, so A5/A7 still hit the real address.
- `li t0,0`-free zero stores that share a register: chained `a = b = 0`. A chain's INNER targets get lui/addiu addresses in registers (`sw zero,(v0)`): `a = b = c = 0` → c,b via regs, a via `at` (BrFrameStatsReset).
- Globals reached via one base register with small offsets = a STRUCT symbol (paint cursor 0x8028D110+0x1C, music state 0x80378FA0); field of a DIFFERENT base = different struct (brush 0x8028D290).
- Strength-reduced `if (0<N){p=&D; do{..}while(p<&D+N*k)}` in drafts = plain `for (i=0;i<N;i++) D[i].f`.
- `switch` with bodies out of numeric order (compare chain sorted, bodies in SOURCE order; the first body may follow the chain inline) - BrOptionsScreen left/right/select/back.
- Operand order of `a + b` is NOT reliably source order; try both, and inline vs local changes it (BrPaintCursorInBox).
- 0xEBC00-style ROM offsets loaded with lui/addiu are LINKED symbols (segment rom starts); 0x80025C00 with lui/ori is a constant.
- GBI: src/tgrally/include/tgr/gbi.h has F3DEX1 macros (gSPMatrix/Viewport/DisplayList, gDPPipeSync/SetCycleType/SetRenderMode/SetCombine/SetPrimColor/FillRectangle, gMoveWd, gRaw). DL code written with the macros matches first try; n64gen/n64lever `gbi` converts Ghidra DL stores to gRaw.
- WORKFLOW THAT PAYS: rewrite T2/T1 as natural C (typed structs/arrays, index loops, float m[4][4]) then run `n64permute.py VA --apply` - it closes operand-order residue in a few compiles (BrScreenFlashDraw 124→0 in 7). Session went 124→206+ T4.
- IDO emits `x / 256.0` as a multiply; the ROM's div.d came from `/ (double)256`.
- Ghidra drops trailing varargs (sprintf "used" arg) and prints data labels as LAB_ - both fixed in n64gen.
- Unlikely-but-true: `a = b; c = 1 << a;` (reads back the just-stored global) vs `1 << b` changes the temp register - try it on register-rename residue.
- STACK SLOTS: IDO gives every named local a slot top-down in declaration order (first = sp+frame-4, e.g. 0x1C), used or not; compiler spill temps go BELOW them. ROM spill at the top slot with no other local = NO named local: write the expression unnamed at every use and IDO CSEs it into a spill temp (BrCarModelStream/Install). An `(int)` cast on one use makes it a different expression and kills the CSE - call with the real pointer type.
- Frame reading: an UNUSED top slot + a spill in the slot below = one short-lived named scalar (reserves the top) and a CSE temp (spilled below). E.g. `kind = car->kind;` then `table[kind].x` everywhere: the table address becomes one spilled temp, and no reload of car->kind after a call (BrCarResetFrames).
- A value from a call return in a named local spills to its home; a param-derived named local gets copy-propagated (temp below).
- Two different spellings of one address in two branches (`&D[i]` vs `D + i`) keep a named var memory-resident (probe lever).
- `p[2] /= p[3]` in place in a local array (not a new float local) put the quotient first in the next mul (BrFogAmount).
- ROM `sll 16; sra 16` into v0 before jr = returns short (BrSfxFreeVoice); gen opt ret_short.
- A running sum whose register is set only at LOOP ENTRY (`move s3,a2` before the loop) is IDO strength reduction of `base + step * (i - 1)` in the source, not a hand-kept accumulator (drawing/image.c, 4 fns).
- Constants: IDO CSEs identical float constants across a branch; writing one `1.0` (double) and the other `1.0f` stops the sharing (BrScreenCameraSet).
- Unused float params still get homed (`swc1 $f12, frame($sp)`): the signature has them.
- CSE BREAKERS (ROM recomputes an address/offset that ours CSEs): the two uses differ in TYPE in the source -- e.g. BrRomReadSize((int)D_000AD400) vs BrRomUnpack(dst, D_000AD400 /*char**/) (BrMainThread); conversely a cast on only ONE use kills a CSE the ROM has (BrCarModelInstall, BrFaultThread). Unprototyped calls avoid spurious casts.
- A struct/table read after a call: ROM keeps `&table[k]` as a spilled temp only if k is a local copy (`kind = car->kind`).
- Mode loops `while (D_8031B318 == f) f;` run a game mode synchronously (BrBootCheck); the ROM lays each rotated as if-do-while.

-  LINE BREAKS ARE A LEVER (2026-09-28): IDO codegen depends on how statements are split across source lines.
