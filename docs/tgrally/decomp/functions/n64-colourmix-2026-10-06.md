# N64 colourmix

*Recorded 2026-10-06.*

> BrPaintColourMix 0x8024B144 (menus/colourmix.c) T4 by hand 2026-10-06, d5e04108, gate 678/0 (session 6c0ee8). Levers: compare-by-name + store-through-const-pointer stops CSE (ROM re-read), ternary assigned to a named float has no cfe temp, indexed array exprs keep s0 live across calls (.livereg), names pointer var for SR order

DONE: T4 d5e04108, image gate 678/0. Drafts w1..w19 + exact_6c0ee8.c in build/tgrally/n64/search/8024B144/ (al.py = shift-tolerant aligned diff; g.sh = grade).

Levers (each read from the ROM, confirmed by compile):
- **ROM re-reads a just-compared global byte** (`lbu t8` compare, `lbu t4` again in the else arm): write the compare by NAME and the stores through a const pointer: `chan = &D; if (D == 2) *chan = 0; else (*chan)++;`. CSE numbers the two loads as different expressions before constprop folds the pointer. Volatile, static, bitfield, switch, ternary, array[0] all still CSE (probes). The sibling BrPaintMirrorMenu's ROM does CSE, so the idiom alone isn't the cause.
- **Every web with save > 0 gets a register or a split (spill)**; only save <= 0 webs are rematerialised. A split forced on a load web gives sw/lw, not a reload, so a ROM reload means "no web", i.e. different expressions.
- **Ternary temp**: `if ((x<0?-x:x) >= k)` makes a cfe float temp below the named locals (one frame word); `mag = x<0?-x:x; if (mag >= k)` uses the named var, no temp.
- **Named `pad = &PADS[i]` reassigned before each call**: ugen emits `addu s0; move a0,s0` but s0 is not in .livereg at the jal, so as1 folds it to `addu a0`. Indexed expressions `D_8036A8E0[D_8028DBBC].f` (real array from tgr/pad.h, not a cast-pointer macro) form one expression web whose .livereg includes s0 at the call, so the ROM's move survives.
- Frame: named locals top-down, then cfe temps, then uopt spill slots (first-fit). `unsigned int ch` copy of a byte global spills to its HOME; `unsigned char ch` gets copy-propagated into a cvt web that spills to a spill slot with a 1-block v0 piece.
- Preheader order i, names-pointer, y, &buf = a user pointer var `name = names` in the for header (SR'd names[i] is inserted after all for-init statements).
- A global only this function touches, sitting in its .data after the init templates: define it in the TU (`unsigned char D_8028DCE0 = 0;`) - resolves the template reloc.
