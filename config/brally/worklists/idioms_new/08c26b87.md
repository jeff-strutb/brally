# Lane 08c26b87 - proven this session

## `float != 0.0f` after an x87 return is one C3 test

Construct: `len = BrVec3Length(&u); if (len != 0.0f) BrVec3DivBy(&u, len);`

Bytes: `fst dword [len]; fcomp dword [0.0]; fnstsw ax; test ah,0x40; jne skip`
(NaN sets C3 too, so a NaN length skips the same as zero.)

Distinguisher: orig one `fcomp` + `jne skip`. A two-sided `if (len > 0.0f || len < 0.0f)`
emits a second `fcomp` / `je` pair and an extra `fld [esp+S]` (BrSndDoppler
0x10060B50, 216 B, MATCH /O2).

## Unroll POD copies; a counted for-loop is `dec/jne`

`pThis->profile[0] = g_BrCtrlDefaults[0];` ×4 → four `mov ecx,0x2a; mov esi,src;
lea edi,dst; rep movsd`. `for (i = 0; i < 4; ++i) pThis->profile[i] = …` → one
copy inside `dec/jne`. Distinguisher: orig 4× `rep movsd` vs recomp 1× plus a
loop (BrCtrlCfgInit 0x10062D00; FIRSTDIV moved +0x1 → +0x8a).

## Re-deref `p->child[k]->field` every store, unroll both zeros and calls

Construct: 6 body zeros then 12 `pB->child[k]->accel.{x,y,z} = 0` with k written
out, then `BrRbAccumOwnForces(pB)` and four `BrRbAccumChildForces(pB, pB->child[k])`.
Each child store reloads `[esi+4/8/c/10]` (`mov ecx,[esi+4]; mov [ecx+0xfc],eax`).
Zero is `xor eax,eax` then `mov [mem],eax`.

Distinguisher: a `for (k = 0; k < 4)` is extra `dec/jne` and missing the 16
field `mov [R+I]` / 9 stores (BrRbAccumAll 0x10064210, 223 B, MATCH /O2).

## f7C8 sibling zeros want `lea ecx,[this+disp]` then `[ecx+n],eax`

After the f3B8 `rep stosd`, orig `lea ecx,[edx+0x7c8]`, fills that slot with
the 0x7B8..0x7C4 immediates, then four `mov [ecx+n],eax` (eax still the stosd
zero). `pThis->f7C8[i] = 0` folds to `mov [edx+0x7c8+n],esi` and lets
`mov eax,9` steal eax before those stores.

Distinguisher: orig `lea ecx,[R+I]` + `mov [R],R` vs recomp `mov [R+I],R`
(BrCtrlCfgInit tail, REGNORM 1+2). A `uint32_t *p = pThis->f7C8` local is
folded away.

## Count-then-cursor increment is `mov eax,ecx; inc eax`, not `inc eax`

Orig (BrReplayAdvance 0x10063AD0 tail): `eax=count[1]; ecx=cursor[1]; dec eax;
cmp ecx,eax; jge; mov eax,ecx; inc eax; mov [cursor[1]],eax`. When cursor is
already in eax (because the store is `a3` abs), VC5 emits `inc eax` and drops
the copy. Distinguisher: orig extra `mov R,R` (2 B). Residual REGNORM 0+1.

## Child-sum order is the fld chain, not the comment

BrRbSolveAccel orig x: `fld child[3].x; fadd [2],[1],[0], t.x`. y: `fld child[0].y;
fadd [1],[2],[3], t.y`. Named `c0..c3` locals spill 6 extra stack movs. Dropping
them + writing that add order reaches REGNORM 0+0 / size match; remaining is
ecx/edx swap on the `accel.z/x/y` integer stores (coloring).
