# Byte exact non negotiable

*Recorded 2026-08-31.*

> HARD RULE - byte-exact is the requirement; never propose the port pivot as an escape from a hard function.

 RULE (2026-08-30, stated firmly): **Byte-exact matching is THE
requirement and stays that way until the project lead explicitly says otherwise.**

**Why:** the project lead decides if/when byte-exact is ever shelved - it will never be
because the assistant went looking for a way out of a hard function.

**How to apply:** Do NOT offer "pivot to the port" (or any other
byte-exactness-optional path) as an option when a function is hard, when
progress stalls, or when framing strategic forks. The port build exists and is
real work, but proposing it as a shortcut around a matching wall reads as
looking for an exit and is unwelcome. When a function is stuck, the honest
menu is: grind it, park it with an honest residue report, or attack a
different byte-exact target - never "stop requiring the bytes." See
[goal-coverage-not-playability](goal-coverage-not-playability.md) and the preeminent rule in the index.
