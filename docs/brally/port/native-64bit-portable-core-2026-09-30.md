# Native 64bit portable core

*Recorded 2026-09-30.*

> DECIDED 2026-09-30: replace the wasm lane with a platform-agnostic 64-bit native core; per-OS renderers Metal (mac) / OpenGL (Linux) / Windows TBD; ILP32 audit results

Project lead decision 2026-09-30: stop the wasm32 intermediary ([macos-port-32bit-wasm-lane](macos-port-32bit-wasm-lane.md)) and build a true 64-bit native port, **platform-agnostic**: one portable core (src/brally/core + shared port specs, fixed-width types so LP64 and LLP64 both work) under a thin platform interface. Windows and Linux builds are planned; do the ILP32 work ONCE, not per OS.

Renderers (project lead choice): **Metal on macOS, OpenGL on Linux, Windows = Vulkan/OpenGL/D3D decided later** "based on what's most superior". Not SDL_GPU. So the renderer interface must be API-neutral; Remastered shaders should have one source translated per API, not three hand ports.

**Why:** the decomp is complete (every BRGlide fn T3/T4), and Remastered host code written against guest memory (W_P/W_LD) grows the migration cost weekly.

**How to apply:** the 32-bit lane stays the shipping app and the lockstep oracle (BR_VCLOCK, per-tick state compare) until the 64-bit core matches it. Float semantics equal the wasm lane (IEEE, no x87) provided arm64 builds use -ffp-contract=off. Plan: ports/common/PORTABLE-CORE.md. Counts: `.venv/bin/python ports/common/tools/lp64audit.py` -> build/brally/analysis/lp64audit/summary.txt (~11s). Port never edits src/brally/ ([port-never-touches-decomp](../decomp/rules/port-never-touches-decomp.md)), so the 64-bit view is GENERATED (LP64 rewriter + data lift from the project lead's DLL) into build/brally/null-soft/src. Biggest structural item: N64-format loaded data (.rca/track/display lists) keeps 4-byte slots -> 32-bit arena offsets via one accessor.

**Revised same day (project lead: "the source is decompiled, 64-bit is an architecture shift, think"):** NO re-running generators. Justification: every fn is certified behaviour-equivalent, so later T3->T4 byte work in src/brally/ never needs to flow to the port.
