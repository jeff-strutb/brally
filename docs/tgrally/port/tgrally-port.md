# Tgrally port

*Recorded 2026-10-05.*

> N64 Top Gear Rally native port in ports/tgrally (Mac first): arena memory model, BE data, lockstep tools vs n64box, and syncing with ongoing N64 M2 decomp work

Started 2026-10-04 after N64 M1 (project lead: "port of the N64 game ... original game first, platform agnostic, mac as first platform"; Windows/remaster deferred). `ports/64b` was renamed `ports/brally` (commit 0ea9f0af).

Design: ports/tgrally/src is a FORK of n64/src (stamp in src/FORKED-FROM). All game memory = one 8 MB arena `tgr_rdram` at original N64 addresses; .data/.bss symbols are asm aliases (gen/arena.s by tools/globals.py). RSP data + cartridge data stay big-endian (be16_t/be32_t/bef_t + BE16/SET32/BEF accessors); scalars native. Pointer tables = native objects (tgr_natives), mapped both ways to original addresses (addr.c, tgr_natpage). libultra's sprintf is ported (platform/libc/xprintf.c), verified identical to the ROM's by tools/printfcheck.py - host printf rounds differently.

Verification: tools/suite.py (all 63 n64box scripts, 14-way, binary snapshot, original's streams cached per script in build/tgrally/boxcache so a full suite takes ~11 s; port runs time out at 180 s so a hang never stalls it), tools/streamcmp.py (whole-run gfx/swap/ai digests vs n64box, 12-way parallel over n64/tools/n64box_scripts), lockstep.py (state + DL at gfx task K), fncheck.py (state at k-th call of a function), watch.py (who writes an address in the ROM). As of 2026-10-04 late: 60/63 scripts bit-identical (gfx, swaps, audio), incl. full championship. The 3 left (paint_shapes/walk/walk2) are the ROM reading an uninitialised stack byte in BrPaintDashRect (c in sp+0x59, written by other functions' frames) - known, not modelled. tools/tgrbox.py = n64box with the ROM-true __d_to_ull and a digest masking a non-CI SETTILE palette (stack residue in BrTexLoad). Renderer (F3DEX 1.21 + Metal) and macOS host not started.

**Why:** the project lead noted N64 M2 keeps respelling n64/src functions while the port is built.
**How to apply:** run `ports/tgrally/tools/sync.py` (3-way merge n64/src base->HEAD into the fork; resolve conflicts keeping port conversions; `--resolved`; it runs errfix/abicheck), rebuild, and re-run streamcmp regressions. Never edit n64/src for port needs ([port-never-touches-decomp](../../brally/decomp/rules/port-never-touches-decomp.md)). Recurring bug classes: float->unsigned must use tgr_f2u/tgr_f2ull (IDO/libultra semantics, host clamps); Apple arm64 packs stack args by declared size so char/short params must match exactly (abicheck checks); BrSample/len-style headers the game wrote BE; local duplicate struct typedefs that pad over fields (use the shared tgr/*.h); data declared with wrong width/type (lift leaves it BE), raw word stores into Gfx/Vtx/Mtx, native pointers in K0 arithmetic, int params receiving native pointers via function pointers.

Sync hazards (2026-10-05, d836d5ab -> 721d5369, 12 conflicts): M2 now writes gbi commands as raw `_g->words.w0/w1` stores; clean 3-way merges pull these into the port silently, so grep `words.w` after every sync and restore the gbi macro. Also watch merged lines that move a native-pointer store (`s->dst = dst`) or drop a declaration the port side still uses (rbquat hh/ww, ctlai block-scoped k). Renderer done since: rcp.c + Metal/soft, see n64-render notes in PORT.md.

Sync 2026-10-05 (721d5369 -> 8ac856b6, commit 79e1f4ad, suite 63/63): heavily restructured M2 functions (carselect, frontbuttons, cardraw, racetick) were REBUILT from decomp HEAD + the base->port conversion diff instead of hunk-picking, because moved blocks merge clean without conversions. Check afterwards that no base line the port converted survives verbatim (difflib base vs port map). Decomp now DEFINES data in TUs (`int D_802724F0 = 0;`, function statics) -> port makes them `extern` (else duplicate symbols vs arena.o at link) and runs staticlift.py on function statics. Second sync same day (-> 4cbfdd8c, 5e2dc9bc, 63/63): decomp MOVED a function to another file (decalpak.c -> image.c) -> clean merge pulls it in unconverted; also clean merges pulled raw `words.w` stores (textstate, weather) and function statics (paintclick). Always grep `words.w[01] *=` and run staticlift on every merged file. Fixed sync.py (deleted file crashed errfix) and link.sh (stale obj of deleted TU).

Renderer lessons (2026-10-05): ALPHA_CVG_SEL (0x2000) alone = alpha := coverage (opaque surfaces, car bodies have vertex alpha 0); only CVG_X_ALPHA (0x1000) cuts by alpha. Back-face cull sign in rcp.c is right (flipping it breaks tracks); car object y is the lateral axis, so do not read +y as roof. RDP 8-sample coverage is modelled by a depth-biased grown copy of each opaque tri (bbox-clipped). Visual sweep tooling: named shots per script + contact sheets; TGR_PIXEL=X,Y probe with numbered tris in TGR_RCPLOG.

RSP facts the renderer got wrong (fixed 2026-10-05 in rcp.c): the ROM's ucode is **F3DEX.NoN 1.21** (no near-plane clip; geometry in front of near is drawn, depth clamped). (1) Forced MVP (movemem 0x9E/98/9A/9C, cars/track objects) must be patched as raw s15.16 halves (s_mvp_fx), never float floor/frac merge -- that was off by 1.0 on tiny negatives = random flat/sheared car. (2) Matrix stack depth resets per task (dram_stack 0x400); without it the start-light gantry lost its parent matrix. (3) G_SETOTHERMODE_L/H ORs the whole w1 (not masked): dust's 0x0F0A0233 at shift 3 sets G_AC_DITHER. (4) Back-face cull via det(x,y,w), also for tris reaching behind the camera (bumper-cam car body). Ground truth when no emulator: TGR_PIXEL + TGR_RCPLOG (now logs mtx/popmtx depth and z/w).

Timing (2026-10-05): n64box (and the port headless) lose a retrace whenever an event is due exactly on the retrace tick (1 in 4 for TGR): N64 clock 4/3 fast. FIXED 2026-10-05 (6f4e71fd): n64box keeps vi_due; all 63 scripts re-recorded (52 n64drive plans regenerated, 11 hand scripts re-timed by screen-change anchors); A7 IDENTICAL; port uses s_vi_due everywhere. Any n64box script made before 6f4e71fd is timed for the 4/3-fast clock. Live-window checks: launch the packaged app with `open -n --env TGR_STATS=1 --stderr FILE app --args --frames N`; focus via osascript activate.

Audio/speed (2026-10-05): (1) TGR re-queues ONE 16 KB ring to the AI and mixes only 0x1000 bytes ahead of the DMA, so the host must get bytes as the modelled AI plays them (io.c ai_update reads RAM at play time; out.c primes LEAD_MS=60 silence when the ring is empty) -- snapshotting at osAiSetNextBuffer sent 96% wrong bytes = "skipping". (2) libultra osInitialize scales osClockRate *3/4 (ROM 0x80265F60); port AND n64box stubbed it out, leaving 62.5 MHz -> mixer timer 13.3 ms and the frame dt (racestart.c D_8028AAD8) 0.025 instead of 0.0333 = whole game at 75% speed. Both fixed; suite 63/63 (paint_* now match too). build.sh does NOT link: run link.sh before suite.py or it tests a stale binary.
