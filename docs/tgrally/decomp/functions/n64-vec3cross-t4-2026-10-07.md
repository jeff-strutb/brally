# N64 vec3cross t4

*Recorded 2026-10-07.*

> BrVec3Cross 0x8022439C T4 2b9c7cf9 (66d9b9) - the stack "t[]" words were uopt-spilled CSE components, not a source array; PC-twin locals z, y with x at its store

BrVec3Cross went from 24 to EXACT on 2026-10-07 (2b9c7cf9, gate 725/0). Source: `float z = Ax*By - Bx*Ay; float y = Az*Bx - Bz*Ax; pOut->x = Ay*Bz - By*Az; pOut->y = y; pOut->z = z;`. This is the PC twin's order, with x written at its store. x as a local gets a home slot (frame 0x28).

Lesson: stack stores of loaded values that look like a hand-written temp array can be uopt SPILLS of common-subexpression webs that lost colouring (6 caller-saved FP colours: f0, f2, f12, f14, f16, f18). Spill stores are inserted after alias analysis, so they don't kill other CSEs. A real local array (or volatile) store does kill every pointer load (`str Mmt` kills ilod).

Diagnostic tools: in the scratch, t/go.sh grades any .o, and toolchain `cc -c` assembles an edited ugen listing (.s) directly, e.g. to test a `.noalias` hint. uopt save = uses + defs per web; ties are coloured lowest web number first.
