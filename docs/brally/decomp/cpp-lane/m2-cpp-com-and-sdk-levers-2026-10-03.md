Plain `/TP` WITHOUT virtuals changes nothing (screened 27 rows). Tell: residue at a COM call (vtable temp ecx/edx, deref vs global store, push order).

16. **Frame layout = lifetime packing + refcount order** (BrSndCarStep 8377e7ea, 2757 B). Block-scoped address-taken locals in different blocks share one slot (micro-TU proven), so a Ghidra local reused across call sites is usually per-block locals; this fixes the frame size. Slot order: higher reference count = lower address; declaration order is inert. Merging a flag's two `= 1` arms into one store after a goto join lowers its count enough to swap slots. Probe with scratch lay16.py (2^n scoping combos scored by slotmap.py mismatch count).
17. **Packed pair `(int)(f*a) + (int)(f*b)*0x10000`**: a float temp always converts the shifted half first; a `double` temp converts in statement order. Splitting `x*K1*K2` into `x = x*K1;` then `x*K2` changes the Pentium schedule (fmul before the index load). An `__int64` read gives the `or lo,hi` zero test. A `cmp r,3 / jle` compare tree is a small switch. Note: vrun.py's RAW counts are insensitive; judge by FIRSTDIV/DIFFS or slotmap.

18. **Block-local aggregate takes a dead aggregate's bytes** (BrRbVelAtPoint/BodyPoint 3f144b2b): a single homed x87 temp landing in a dead PARAMETER slot instead of a dead local's slot = write the temps as a block-local BrVec3 (c.x/c.y/c.z); VC5 lifetime-packs it over the dead copy. Float temps / arrays / decl order were the old dead list.
19. **"Rounding points" hacks (BR_*_ROUND int-image macros) are usually just homed float locals**: VC5 does `fst [home]`, uses the stack copy first, reloads the float later; two values in one slot = two locals with disjoint lifetimes, NOT CSE temps. Rewriting with plain float locals: BrCarPathEval 1061->937/937, BrMat3Solve 579->379/417, BrMat4FromCarState 433->361/363 (candidates in m2_candidates/NOTES).
20. **Head hoisting**: an instruction placed AFTER `fnstsw/test` but before `jcc` (load or store) = the same statement written at the head of BOTH arms (VC5 hoists identical first instructions). Same for a store between `fcom` and the branch (abs tails). A store at a join with a value in the same reg from both arms = the assignment written at the END of each arm (tail-merged).
21. Repeated address math (`f8c + f90*0x28`) written INLINE at each use, not via a temp, fixed operand-load order; a reused Ghidra local (`fVar2` = seg value AND t) is often 2-3 locals that VC5 packed into one slot: split them and pick which pairs share by sweeping.
